# 🏥 VisiPulse
### نظام الإنذار المبكر وحوكمة البنية التحتية للمنشآت الصحية

نظام محوسب مبني بلغة Python باستخدام Streamlit + SQLAlchemy + SQLite، يوفّر ثلاث بوابات
منفصلة تماماً حسب دور المستخدم (RBAC)، مع ضوابط أمنية وحوكمة بيانات مصمَّمة لتتماشى مع
الممارسات المتعارف عليها ضمن متطلبات الهيئة الوطنية للأمن السيبراني (NCA ECC) ومتطلبات
اعتماد المستشفيات (CBAHI) المتعلقة بأمن المعلومات وسجلات التدقيق.

---

## 1) هيكلية المشروع

```
visipulse/
├── app.py                  # نقطة التشغيل الرئيسية (streamlit run app.py)
├── models.py                # نماذج قاعدة البيانات (SQLAlchemy ORM)
├── database.py               # إعداد المحرك/الجلسة + قيود عدم قابلية تعديل سجل التدقيق
├── security.py                # التجزئة، سياسة كلمة المرور، تشفير الحقول (Fernet)
├── audit.py                    # سجل التدقيق: سلسلة تجزئات SHA-256 + دالة التحقق
├── auth.py                      # منطق تسجيل الدخول، القفل المؤقت، مهلة الخمول
├── seed.py                       # تهيئة أولية: حسابات + بيانات تجريبية
├── generate_key.py                # أداة توليد مفتاح Fernet
├── ui/
│   ├── it_portal.py                 # بوابة تقنية المعلومات (6 أقسام)
│   ├── executive_portal.py           # بوابة الإدارة العليا
│   └── employee_portal.py             # بوابة الموظف
├── requirements.txt
├── .env.example
└── .gitignore
```

## 2) التشغيل السريع

```bash
# 1. إنشاء بيئة افتراضية (موصى به)
python -m venv .venv
source .venv/bin/activate      # على ويندوز: .venv\Scripts\activate

# 2. تثبيت المتطلبات
pip install -r requirements.txt

# 3. إعداد ملف البيئة
cp .env.example .env
python generate_key.py         # انسخ الناتج إلى ENCRYPTION_KEY داخل .env

# 4. تهيئة قاعدة البيانات والحسابات الأولية
python seed.py
# ⚠️ سيطبع السكربت كلمات مرور مؤقتة عشوائية لثلاثة حسابات (it_admin / hospital_director / employee1)
#    احفظها فوراً في مكان آمن؛ لن تظهر مرة أخرى، وسيُطلب تغييرها إجبارياً عند أول دخول.

# 5. تشغيل التطبيق
streamlit run app.py
```

## 3) هيكلية الأدوار والبوابات (RBAC)

| الدور | البوابة | المحتوى |
|---|---|---|
| `it` | تقنية المعلومات | الصحة الإلكترونية، الدعم الفني، البنية التحتية والشبكات، الأنظمة والتطبيقات، سجل التدقيق الأمني، إدارة المستخدمين |
| `executive` | الإدارة العليا | مؤشرات الأداء (KPI) ومستوى الخدمة (SLA)، اعتماد القرارات الاستراتيجية، تقرير الامتثال |
| `employee` | الموظف العادي | الإنذار الاستباقي ورصد الأعطال، إرسال البلاغات ومتابعتها |

> تمت إضافة تبويب **إدارة المستخدمين** ضمن بوابة IT (لم يُذكر صراحة في المتطلبات الأصلية) لأن
> أي نظام RBAC فعلي يحتاج جهة مخوَّلة لإنشاء الحسابات وفك القفل عنها؛ أُسندت هذه الصلاحية إلى
> تقنية المعلومات بوصفها الجهة المسؤولة عادة عن إدارة الهوية والوصول (IAM) في المنشآت الصحية.

## 4) الضوابط الأمنية المطبَّقة

- **سياسة كلمة مرور صارمة**: 12 حرفاً كحد أدنى، حرف كبير + صغير + رقم + رمز خاص، منع احتواء
  اسم المستخدم، رفض كلمات المرور الشائعة، منع إعادة استخدام آخر N كلمات مرور، وانتهاء صلاحية
  دورية (كل القيم قابلة للتعديل عبر `.env`).
- **القفل المؤقت للحساب** بعد تجاوز عدد محاولات الدخول الخاطئة (افتراضياً 5 محاولات / قفل 15 دقيقة).
- **مهلة خمول الجلسة**: تسجيل خروج تلقائي بعد فترة عدم نشاط (افتراضياً 15 دقيقة)، مع سجل للحدث.
- **تشفير الحقول الحساسة** (البريد الإلكتروني، رقم الجوال، عناوين IP) باستخدام `cryptography.Fernet`
  ومفتاح مُدار عبر متغيرات بيئة `.env` (لا يُخزَّن أي مفتاح داخل الكود المصدري).
- **سجل تدقيق غير قابل للتلاعب**، محمي بطبقتين مستقلتين:
  1. سلسلة تجزئات SHA-256 (Hash Chain) تكشف أي تعديل لاحق على أي سجل قديم.
  2. قيود (Triggers) على مستوى قاعدة البيانات تمنع تنفيذ `UPDATE`/`DELETE` على جدول `audit_log` تماماً.
- **تجزئة كلمات المرور** عبر `bcrypt` (لا تُخزَّن كلمات المرور كنص صريح إطلاقاً).

## 5) ملاحظة أمانة حول نطاق الالتزام التنظيمي

هذا النظام يطبّق مجموعة ضوابط تقنية شائعة ومتوافقة مع روح متطلبات NCA ECC وCBAHI المتعلقة
بإدارة الهوية والوصول وسجلات الأحداث. لكنه **لا يُشكّل بذاته شهادة امتثال أو ضماناً لاجتياز تدقيق
رسمي**، إذ يتطلب ذلك أيضاً عناصر تنظيمية وتقنية إضافية خارج نطاق تطبيق برمجي واحد، من أبرزها:

- تكامل مع بيئة مصادقة مركزية (Active Directory / SSO) بدل حسابات محلية مستقلة.
- تشفير كامل لقاعدة البيانات أثناء التخزين (Encryption at Rest) وإدارة مفاتيح عبر HSM/KMS مخصص.
- إعادة توجيه سجلات التدقيق إلى نظام SIEM مركزي وتخزين WORM لضمان عدم قابلية التلاعب على
  مستوى البنية التحتية بأكملها، لا على مستوى التطبيق فقط.
- تشغيل خلف TLS/HTTPS وجدار حماية تطبيقات ويب (WAF)، واختبار اختراق دوري.
- سياسات تنظيمية وإجرائية موثقة (تصنيف بيانات، استمرارية أعمال، تدريب توعوي) مكمّلة للضوابط التقنية.
- استبدال SQLite بقاعدة بيانات مؤسسية (PostgreSQL/SQL Server) مع نسخ احتياطي واستعادة مُختبرة
  عند الانتقال إلى بيئة إنتاج حقيقية متعددة المستخدمين.

## 6) بيانات الدخول الأولية

يُنشئ `seed.py` ثلاثة حسابات تجريبية بكلمات مرور مؤقتة عشوائية (تُطبع في الطرفية عند التشغيل فقط):

| اسم المستخدم | الدور |
|---|---|
| `it_admin` | تقنية المعلومات |
| `hospital_director` | الإدارة العليا |
| `employee1` | موظف |

جميعها بحالة `must_change_password=True`، بحيث يُطلب تعيين كلمة مرور جديدة مطابقة للسياسة
فور أول تسجيل دخول.
